## 2. WHAT IS RUNNING RIGHT NOW (the graded-overlap experiment — advisor point 4)

**The question:** is the input-selectivity a **presence detector** (binds whenever clusters co-exist)
or a **computation** (encodes *how much* they overlapped)? Sweep the temporal offset of cluster B
continuously; measure cross_w vs the **measured co-ignition duration** (`coignition_s` in each record).

**Command form (already launched):**
```
python sweep/po9_unitB_input_selectivity.py --worker <o> --n 5 --lamF 214 --cond graded --offset <o> --grouping twocluster --tag grade_o<o>
```
offsets running: {10, 15, 20, 25, 30} s, 5 draws each; plus offset 0 = SYNC (have 8 draws) and
offset 40 = STAGGER (cross_w=0). Output: `results/po9_unitB/po9_unitB_grade_o<o>_w<o>.jsonl`.

**The verdict rule (pre-registered, Amendment 2):**
- **STEP** (cross_w ≈ full for any co-ignition > ~0, cliffs to 0): presence detector. The null.
- **GRADED** (cross_w rises smoothly with co-ignition duration, width ~ dimer lifetime): a computation
  over a continuous input quantity — the first thing that clears the §8 bar.
- **Early hint (one draw):** offset=10 → 11 s co-ignition → cross_w ≈ 1050 ≈ full SYNC (~25 s co-ign,
  ~848). That smells STEP/fast-saturating. The **low-offset end (25, 30 → very short co-ignition)** is
  what resolves it — do not conclude before those land.
