## Why it happened — and it is not the mistake I thought I was avoiding

I used explicit-path `git add`, exactly as the isolation rule requires:

```
git add <my four paths>
git commit -m "..."
```

**That is not sufficient in a shared worktree.** `git add` stages only my paths, but
`git commit` commits **the entire staged index** — including anything another PO staged
concurrently. The isolation rule as I was following it protects against `git add -A`; it does
**not** protect against a co-tenant staging files between my `add` and my `commit`.

**The form that actually isolates is a pathspec on the commit itself:**

```
git commit -- <paths>        # or: git commit --only <paths>
```

which commits *only* those paths regardless of index state. I have switched to it. This
message is the first commit made that way.
